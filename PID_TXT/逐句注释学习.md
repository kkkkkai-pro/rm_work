# 一、pid.h —— PID 模块的"说明书"

## 1. 文件头注释（第 1~10 行）

```c
/*
 * pid.h
 *
 * 位置式 PID，带以下可开关的增强功能（对应学习要求）：
 *   1. 积分限幅 + 输出限幅（必备，防积分饱和）
 *   2. 死区 PID       ：|误差| < deadband 时认为到位，输出 0 并清积分
 *   3. 积分分离 PID   ：|误差| > int_sep_err 时不积分，防止大误差阶段积分饱和
 *   4. 前馈 PID       ：out += kff * (目标值微分)，即"角速度一阶前馈"
 * 不需要的功能把对应参数置 0 即可。
 */
```

**逻辑：** 这是一个"位置式 PID"（每一拍直接根据当前误差算出完整输出，而不是增量式那种"输出 += 增量"）。设计思想是把四个增强功能全部做成**参数可开关**：用就传非 0 值，不用就传 0。这样一份代码可以当普通 PID、死区 PID、积分分离 PID、前馈 PID 任意组合使用，不用写四个版本。

## 2. 防止重复包含（第 11~12 行）

```c
#ifndef PID_H
#define PID_H
```

**逻辑：** C 头文件的经典保护写法。如果同一个 `.c` 文件（或间接包含链）两次 `#include "pid.h"`，第二次进来时 `PID_H` 已经被定义，预处理器直接把整段内容跳过，避免结构体被重复定义导致编译错误。

## 3. C++ 兼容保护（第 14~16 行）

```c
#ifdef __cplusplus
extern "C" {
#endif
```

**逻辑：** 如果这个头文件被 C++ 代码包含，C++ 编译器会给函数名做"名字修饰"（name mangling），导致链接不到 C 写的实现。`extern "C"` 告诉 C++ 编译器"这些函数按 C 的规则处理"。用纯 C 编译时 `__cplusplus` 未定义，这段自动跳过。

## 4. PID 结构体定义（第 18~38 行）

```c
typedef struct
{
    /* ----- 由用户设定的参数 ----- */
    float kp;
    float ki;
    float kd;
    float kff;            /* 前馈系数：目标值一阶导数的增益 */
    float dt;             /* 控制周期（秒），如 0.001 */
```

**逻辑：**
- `kp`：比例系数。误差乘它就是比例输出，负责"反应快"。
- `ki`：积分系数。对历史误差累加，负责"消除静差"（P 控制单独用时永远差一点不到位，I 靠累积把这个差磨掉）。
- `kd`：微分系数。对误差变化率起作用，负责"抑制超调、预判刹车"。
- `kff`：前馈系数，普通 PID 没有这一项。作用后面在 `PID_Calc` 里细讲。
- `dt`：控制周期（秒）。积分要乘 `dt`（误差×时间才是面积），微分要除 `dt`（差值÷时间才是变化率）。把它做成参数而不是写死，代码就与时钟频率解耦。

```c
    float integral_limit; /* 积分限幅 */
    float output_limit;   /* 输出限幅 */
```

**逻辑：** 两个保险丝。
- 积分限幅：积分项是累加器，一旦电机被卡死或长时间误差大，它会累积成天文数字（积分饱和），等障碍消失时输出会爆炸造成巨大超调。限制它的绝对值上限。
- 输出限幅：电机能接受的最大电流是有限的（GM6020 是 ±10000），PID 算出的数值必须裁剪到物理设备能承受的范围内。

```c
    float deadband;       /* 死区：|err| 小于该值时输出 0 */
    float int_sep_err;    /* 积分分离阈值：|err| 大于该值时不积分 */
```

**逻辑：** 两个开关参数，置 0 即关闭对应功能。
- 死区：实际系统有静摩擦/齿隙，误差极小时电机会被 PID 的小输出搞得在目标附近来回抖动（极限环振荡）。干脆设一个"该范围内就当到了"的输出零区。
- 积分分离阈值：刚给目标一个大幅度阶跃时，误差巨大，这时积分会疯狂累积。约定"误差超过这个阈值就不积分"，等误差小到一定程度再开始积分。

```c
    /* ----- 内部状态（用户不要直接改） ----- */
    float integral;       /* 积分累加器 */
    float prev_err;       /* 上一次的误差 */
    float prev_ref;       /* 上一次的目标值（前馈用） */
    float output;         /* 最近一次输出 */
} PID_t;
```

**逻辑：** 这四项是"有记忆"的状态变量，必须由算法自己维护，用户乱改会破坏连续性。
- `integral`：历史误差面积的累计，每拍 `+= err*dt`。
- `prev_err`：微分项要用 `这次的误差 - 上次的误差` 得到误差变化率，所以要记住上一拍的误差。
- `prev_ref`：前馈项要算目标值的变化率 `(这次的ref - 上次的ref)/dt`，所以要记住上一拍的目标值。
- `output`：保存最近一次输出，便于调试器观察和上层读取。

## 5. 函数声明（第 40~51 行）

```c
/* 初始化。不需要的功能对应参数填 0。 */
void PID_Init(PID_t *pid,
              float kp, float ki, float kd, float kff,
              float dt,
              float integral_limit, float output_limit,
              float deadband, float int_sep_err);

/* 计算一次 PID。ref = 目标值，fdb = 反馈值，返回输出。 */
float PID_Calc(PID_t *pid, float ref, float fdb);

/* 清空积分和历史误差（电机掉线、切换目标时调用）。 */
void PID_Reset(PID_t *pid);
```

**逻辑：** 三个函数构成最小 API：
- `PID_Init`：传入全部参数并清零内部状态。
- `PID_Calc`：核心函数，**每调用一次就执行一个控制周期**（离散化 PID 的本质：连续微积分被拍成一次次乘法累加）。`ref` = reference 目标值，`fdb` = feedback 反馈值。
- `PID_Reset`：状态清零。什么时候要清？电机掉线后再上线（旧积分是基于错误数据累积的）、或者控制模式切换时，避免"陈年旧账"污染当前输出。

## 6. 收尾（第 53~57 行）

```c
#ifdef __cplusplus
}
#endif

#endif /* PID_H */
```

**逻辑：** 分别闭合开头开的 `extern "C"` 花括号和 `#ifndef` 条件块。注释里再写一遍 `PID_H` 是为了方便读者知道这是哪一对的 `#endif`。

# 二、pid.c —— PID 算法的实现

## 1. 头文件包含（第 1~3 行）

```c
#include "pid.h"

#include <math.h>
```

**逻辑：** 引入自己的头文件 `pid.h`（让编译器检查实现和声明一致）；`math.h` 提供 `fabsf()`（浮点绝对值函数），死区和积分分离都要判断 `|误差|`。

## 2. 限幅工具函数（第 5~16 行）

```c
static float Limit(float value, float min_value, float max_value)
{
    if (value < min_value)
    {
        return min_value;
    }
    if (value > max_value)
    {
        return max_value;
    }
    return value;
}
```

**逐句逻辑：**
- `static`：这个函数只在 pid.c 内部使用，加 `static` 表示"文件私有"，避免和其它文件里的同名函数冲突，也让编译器有机会做内联优化。
- 参数设计为通用的 `(值, 下限, 上限)` 三段式，积分限幅和输出限幅都能复用，不用写两遍。
- 第一句 `if`：小于下限就钳到下限；第二句 `if`：大于上限就钳到上限；都不满足说明在范围内，原样返回。
- 这是一个**饱和（saturation）**处理：宁可砍掉多余部分，也不让数值超出物理/安全边界。

## 3. PID_Init 初始化（第 18~36 行）

```c
void PID_Init(PID_t *pid,
              float kp, float ki, float kd, float kff,
              float dt,
              float integral_limit, float output_limit,
              float deadband, float int_sep_err)
```

**逻辑：** 第一个参数是结构体指针——C 语言里"给函数一个结构体让它填内容"的标准做法，不用返回值，直接原地改调用者的变量。

```c
{
    pid->kp = kp;
    pid->ki = ki;
    pid->kd = kd;
    pid->kff = kff;
    pid->dt = dt;

    pid->integral_limit = integral_limit;
    pid->output_limit = output_limit;
    pid->deadband = deadband;
    pid->int_sep_err = int_sep_err;

    PID_Reset(pid);
}
```

**逐句逻辑：**
- `pid->kp = kp;` 等：`->` 是"通过指针访问成员"的运算符。形参名和成员名同名是刻意的，一一对应无脑赋值，清晰不易错。
- 参数分两组：第一组是控制律参数（k 系列 + dt），第二组是限幅/开关参数。分组赋值只是排版，无功能差别。
- 最后调用 `PID_Reset(pid)`：初始化必须包含"清零内部状态"，否则结构体里是随机垃圾值，第一拍微分项就会算出 `(err - 垃圾)/dt` 爆炸。复用已有函数，不用重复写清零代码。

## 4. PID_Calc 核心计算（第 38~98 行）

```c
float PID_Calc(PID_t *pid, float ref, float fdb)
{
    float err;
    float ref_dot;
    float p_out, i_out, d_out, ff_out;

    err = ref - fdb;
```

**逐句逻辑：**
- 局部变量集中声明在函数开头（嵌入式 C 的常见风格，部分老编译器要求这样）。
- `err = ref - fdb`：误差 = 目标 − 反馈。**整段代码的核心量**。注意符号约定：误差为正说明"还没到、要加速"，后面所有项都基于这个约定。

### 4.1 死区处理（第 46~57 行）

```c
    /*
     * 死区：误差小于死区宽度时认为已经到位。
     * 输出 0、清积分，防止电机在目标位置附近来回抖动。
     */
    if (fabsf(err) < pid->deadband)
    {
        pid->integral = 0.0f;
        pid->prev_err = err;
        pid->prev_ref = ref;
        pid->output = 0.0f;
        return 0.0f;
    }
```

**逐句逻辑：**
- `fabsf(err) < deadband`：浮点绝对值小于死区宽度 → 进入"到位模式"。若 `deadband = 0`，这个条件几乎永远不成立，功能关闭。
- `integral = 0`：到位后积分清零。不清理的话微小误差长期累积会让 I 项偷偷顶开输出，破坏静止。
- `prev_err = err; prev_ref = ref;`：**这两句极易漏但非常关键**。记录了本拍状态后立刻 `return`，如果不更新历史值，下一拍重新进入计算时微分项会出现 `(err - 很久以前的prev_err)/dt` 的虚假跳变；前馈同理。保持"每次调用结束都要让历史值跟上当前值"这一不变量。
- `output = 0; return 0.0f;`：输出归零并直接返回，**跳过后面所有计算**——到位了就彻底歇着。

### 4.2 比例项（第 59~60 行）

```c
    /* 比例项 */
    p_out = pid->kp * err;
```

**逻辑：** 最简单直接的一项：误差越大输出越大，响应最快。`kp` 大则响应快但容易超调和振荡。

### 4.3 积分项 + 积分分离（第 62~75 行）

```c
    /*
     * 积分项（积分分离）：
     * 误差很大时（比如刚给阶跃、电机还没动）不积分，
     * 否则积分会一路累积到饱和，到目标附近时造成大超调。
     * int_sep_err = 0 表示关闭积分分离（始终积分）。
     */
    if ((pid->int_sep_err <= 0.0f) || (fabsf(err) <= pid->int_sep_err))
    {
        pid->integral += err * pid->dt;
        pid->integral = Limit(pid->integral,
                              -pid->integral_limit,
                              pid->integral_limit);
    }
    i_out = pid->ki * pid->integral;
```

**逐句逻辑：**
- 条件 `(int_sep_err <= 0) || (|err| <= int_sep_err)`：两个条件用"或"连接，只要满足一个就积分。第一个条件是**总开关**：传 0 或负数表示"关闭积分分离，永远积分"；第二个条件是**阈值判断**：误差不够大才积分。比如阈值设 5°，误差 20° 时不积分，误差磨到 4° 开始积分。
- `integral += err * dt`：离散积分的本质——把误差曲线下的面积用一个个小矩形累加近似。`err*dt` 是本拍的小矩形面积。
- `Limit(...)`：立刻钳位，防止下一行用的时候已经是天文数字。下限写 `-integral_limit`、上限写 `integral_limit`，实现对称限幅。
- 注意 `i_out` 的计算在 `if` 外面：不积分的那些拍，积分保持上一次的值（相当于 I 项"保持"而不是清零），输出依然包含历史积分的作用。

### 4.4 微分项（第 77~78 行）

```c
    /* 微分项（对误差微分） */
    d_out = pid->kd * (err - pid->prev_err) / pid->dt;
```

**逻辑：** `(err - prev_err)/dt` = 误差变化率（离散微分）。误差在快速缩小（电机正快速逼近目标）时，D 项为负，相当于"提前踩刹车"，抑制 P 项造成的冲过头。分母 `dt` 把"每拍变化量"换算成"每秒变化量"，系数才有确定物理意义。

### 4.5 前馈项（第 80~87 行）

```c
    /*
     * 前馈项（角速度一阶前馈）：
     * 目标是角度时，目标角速度 = d(ref)/dt。
     * 前馈把"目标要动多快"直接加进输出，电机不用等误差
     * 积出来才加速，能明显加快响应。
     */
    ref_dot = (ref - pid->prev_ref) / pid->dt;
    ff_out = pid->kff * ref_dot;
```

**逻辑：** 普通 PID 是"错了才改"的反馈控制：目标一动，必须等误差出现、P 一项项累积，电机才开始加速。前馈是"还没错就先动"：直接对目标值求导，预测"目标此刻要求多快的速度"，乘个系数 `kff` 直接加进输出。反馈要等误差，前馈零延迟，两者互补。`kff = 0` 时此项自动消失，功能关闭。

### 4.6 输出合成与限幅（第 89~92 行）

```c
    pid->output = p_out + i_out + d_out + ff_out;
    pid->output = Limit(pid->output,
                        -pid->output_limit,
                        pid->output_limit);
```

**逻辑：** 四个分量线性叠加成总输出，再钳位到 ±output_limit。这就是"位置式"的含义：每次算出的是**完整的输出值**，不是增量。

### 4.7 保存历史并返回（第 94~98 行）

```c
    pid->prev_err = err;
    pid->prev_ref = ref;

    return pid->output;
}
```

**逻辑：** 把本拍的误差和目标值存入历史，供下一拍算微分/前馈。**这一步和死区分支里的那两句是同一个不变量**：无论走哪条路径，`PID_Calc` 返回时 `prev_err`/`prev_ref` 一定已经更新为本拍的值。

## 5. PID_Reset 状态清零（第 100~106 行）

```c
void PID_Reset(PID_t *pid)
{
    pid->integral = 0.0f;
    pid->prev_err = 0.0f;
    pid->prev_ref = 0.0f;
    pid->output = 0.0f;
}
```

**逻辑：** 只清四个内部状态，**不动用户参数**（k 值、限幅保留）。典型场景：电机 CAN 断线后重新上线，之前基于旧数据积出的 `integral` 和过期的 `prev_err` 都是错的，清零重新开局。注意 `prev_*` 清零后第一拍的微分/前馈会基于"从 0 到当前值"的跳变算出一个尖峰——所以更严谨的做法是在重新运行的第一拍手动调用一次 `PID_Calc` 来"预热"历史值（本项目用"初始化目标=当前位置"的策略绕开了这个问题，见 control_task.c）。

# 三、gm6020.h —— 电机驱动的"说明书"

## 1. 文件头注释（第 1~13 行）

```c
/*
 * gm6020.h
 * ...（功能、接线说明：CAN1 的 1 脚 CANL / 2 脚 CANH、共地要求、拨码 ID=1、24V 供电）
 */
```

**逻辑：** 头注释承担了"硬件接口文档"的角色。CAN 是差分总线，**必须共地**（否则差分参考点漂移，通信随机出错）；发送 ID 规则、供电电压这些现场信息直接写在离代码最近的地方，防止接线时翻箱倒柜找手册。

## 2. 可配置宏（第 24~44 行）

```c
#define GM6020_MOTOR_ID     1u
```

**逻辑：** 电机尾部拨码开关设的 ID。`u` 后缀表示无符号数。这是整个文件唯一需要按现场改的量。

```c
/* 发送帧标识符：ID1~4 用 0x1FF，ID5~7 用 0x2FF */
#if (GM6020_MOTOR_ID <= 4u)
#define GM6020_TX_ID        0x1FFu
#else
#define GM6020_TX_ID        0x2FFu
#endif
#define GM6020_RX_ID        (0x204u + GM6020_MOTOR_ID)
```

**逻辑：** GM6020 的 CAN 协议规定（这是电机的硬件协议，不是我们能改的）：
- 控制电流：1~4 号电机收 `0x1FF`，5~7 号收 `0x2FF`；一条报文的 8 字节里按电机 ID 分配字节位置（ID1 用 Byte0/1，ID2 用 Byte2/3……）。
- 反馈报文：每个电机主动回 `0x204 + ID`（ID1 → `0x205`）。
用预处理器 `#if` 在**编译期**根据拨码 ID 自动选发送 ID，运行时零开销，改电机 ID 不用动其它代码。

```c
#define GM6020_CURRENT_MAX  10000
#define GM6020_TIMEOUT_MS   100u
#define GM6020_ENCODER_FULL 8192.0f
```

**逻辑：** 三个协议/硬件常量：
- `±10000`：GM6020 手册规定的电流指令量程（无符号 16 位里放有符号值）。
- `100ms`：反馈超时阈值。电机正常每几毫秒回一帧，超过 100ms 没消息 = 线断了/电机断电/电机坏了。
- `8192`：编码器单圈总刻度（2^13 = 8192），机械角分辨率 = 360°/8192 ≈ 0.044°。

## 3. 电机状态结构体（第 48~63 行）

```c
typedef struct
{
    /* 原始反馈 */
    uint16_t raw_angle;          /* 机械角原始值 0~8191 */
    int16_t  speed_rpm;          /* 转速 rpm */
    int16_t  current;            /* 转矩电流（反馈值） */
    uint8_t  temperature;        /* 温度 ℃ */

    /* 解算值 */
    float    angle_deg;          /* 当前圈内的角度 0~360 */
    float    total_angle_deg;    /* 连续累计角度（跨圈不归零），位置环用它 */

    /* 状态 */
    uint32_t last_update_ms;     /* 最后一次收到反馈的 HAL_GetTick() 时间 */
    uint8_t  online;             /* 1 = 在线 */
} GM6020_t;
```

**逻辑：** 按"原始 → 解算 → 状态"三层分组，数据来源和用途一目了然：
- 前 4 项：从 CAN 帧里**直接解出的原始数据**，类型与协议严格对应（角度无符号、转速电流有符号——有符号才能表示反转/负电流）。
- `angle_deg`：换算成角度的圈内值，做显示用。
- `total_angle_deg`：**本项目最重要的变量**。电机反馈的角度永远是 0~8191 循环的（单圈），而位置控制需要"转了多少圈"的连续量，这个值由 gm6020.c 里的跨圈补偿算法累计出来。
- `last_update_ms` + `online`：一对"活性检测"字段。中断里更新时间戳并置 online，任务里检查时间戳是否过期。

## 2. CAN_UserInit 过滤器配置与启动（第 9~37 行）

```c
void CAN_UserInit(void)
{
    CAN_FilterTypeDef filter;

    filter.FilterMode = CAN_FILTERMODE_IDMASK;     /* 掩码模式 */
    filter.FilterScale = CAN_FILTERSCALE_32BIT;    /* 32 位过滤器 */
    filter.FilterIdHigh = 0x0000;
    filter.FilterIdLow = 0x0000;
    filter.FilterMaskIdHigh = 0x0000;              /* 掩码全 0 = 全部接收 */
    filter.FilterMaskIdLow = 0x0000;
    filter.FilterFIFOAssignment = CAN_RX_FIFO0;    /* 放进 FIFO0 */
    filter.FilterBank = 0;                         /* 用过滤器组 0 */
    filter.FilterActivation = ENABLE;
```

**逐句逻辑：** 掩码模式（IDMASK）的匹配规则是：**帧ID & 掩码 == 过滤器ID & 掩码** 则通过。这里 ID 全 0、掩码全 0，任何 ID 与 0 相与都得 0，永远等于过滤器 ID → **所有帧全部接收**。学习/调试阶段不想漏掉总线上任何帧，这是最简单的配置；产品阶段应配置成只收自己关心的 ID，减轻 CPU 负担。
- FIFO 选择 FIFO0：STM32 的 CAN 有两套接收 FIFO（各 3 级邮箱），这里固定用 FIFO0，中断也对应 `RxFifo0` 回调。
- FilterBank = 0：STM32 有多个过滤器组（C 型板 14 组），用第 0 组。
- 全部赋值完再 `ENABLE`，一次写入生效。

```c
    if (HAL_CAN_ConfigFilter(&hcan1, &filter) != HAL_OK)
    {
        Error_Handler();
    }
    if (HAL_CAN_Start(&hcan1) != HAL_OK)
    {
        Error_Handler();
    }
    if (HAL_CAN_ActivateNotification(&hcan1,
                                     CAN_IT_RX_FIFO0_MSG_PENDING) != HAL_OK)
    {
        Error_Handler();
    }
}
```

**逐句逻辑：** 三步，顺序不能乱：
1. `ConfigFilter`：写过滤器。必须先于启动，否则启动后收到的帧用默认过滤器配置（默认全拒收）。
2. `Start`：让 CAN 控制器离开初始化模式、真正上线收发。
3. `ActivateNotification`：使能"FIFO0 收到消息挂起"中断。之后每来一帧，HAL 自动调 `HAL_CAN_RxFifo0MsgPendingCallback`。
- 每步检查 `HAL_OK`，失败进 `Error_Handler()` 死循环：**初始化阶段任何一步失败都是致命硬件/配置问题，与其带病运行不如停在原地**，配合调试器一眼定位。

## 3. FeedbackDecode 反馈解码 + 跨圈累计（第 41~84 行）

这是全工程最有算法含量的一段。

```c
static void FeedbackDecode(const uint8_t data[8])
{
    static uint16_t s_last_raw;
    static uint8_t  s_first_frame;
    int32_t delta;

    g_motor.raw_angle   = ((uint16_t)data[0] << 8) | data[1];
    g_motor.speed_rpm   = (int16_t)(((uint16_t)data[2] << 8) | data[3]);
    g_motor.current     = (int16_t)(((uint16_t)data[4] << 8) | data[5]);
    g_motor.temperature = data[6];
```

**逐句逻辑：**
- `static` 局部变量：只初始化一次、跨调用保持值——正是"记历史"需要的语义（`s_last_raw` 记住上帧角度，`s_first_frame` 记住是否见过第一帧）。且文件私有。
- CAN 数据是大端（高字节在前）：`(uint16_t)data[0] << 8 | data[1]` = 高字节左移 8 位拼上低字节，重组出 16 位原始值。先转 `(uint16_t)` 防止 `uint8_t` 提升成 `int` 时移位行为出问题。
- 转速和电流**必须转 `int16_t`**：协议里它们是有符号量，不转的话负值（反转、负电流）会被解释成 65535 附近的大正数，控制立刻发散。

```c
    /* 圈内角度 0~360 */
    g_motor.angle_deg =
        (float)g_motor.raw_angle * 360.0f / GM6020_ENCODER_FULL;
```

**逻辑：** 线性映射：0~8191 → 0~360°。注意先乘 360 再除 8192，并且先转 float——顺序错了先做整数除法精度就丢了。

```c
    if (s_first_frame == 0u)
    {
        /* 第一帧：以当前位置作为连续角度的零点 */
        s_last_raw = g_motor.raw_angle;
        g_motor.total_angle_deg = 0.0f;
        s_first_frame = 1u;
    }
```

**逻辑：** 第一帧没有"上一帧"可比较，无法算增量。干脆定义"上电瞬间的位置就是 0°"，之后所有角度都是相对这个点的累计值。**这就是控制里"目标初始化=当前位置"配合防止上电猛冲的另一半**（另一半在 control_task.c）。

```c
    else
    {
        delta = (int32_t)g_motor.raw_angle - (int32_t)s_last_raw;

        /* 差值超过半圈 = 跨圈跳变，做 8192 补偿 */
        if (delta > (int32_t)(GM6020_ENCODER_FULL / 2.0f))
        {
            delta -= (int32_t)GM6020_ENCODER_FULL;
        }
        else if (delta < -(int32_t)(GM6020_ENCODER_FULL / 2.0f))
        {
            delta += (int32_t)GM6020_ENCODER_FULL;
        }

        g_motor.total_angle_deg +=
            (float)delta * 360.0f / GM6020_ENCODER_FULL;
        s_last_raw = g_motor.raw_angle;
    }
```

**逐句逻辑（核心难点：跨圈跳变补偿）：**
- `delta`：本帧原始角度 − 上帧原始角度。转 `int32_t` 再减是为了让结果带符号（`uint16_t` 相减会下溢成大正数）。
- 问题场景：电机正转跨过 0 点时，原始值从 8190 跳到 3，机械上只动了 ~5 个刻度，`delta` 却算出 3 − 8190 = **−8187**——一个假的巨大反转。
- 判据：**真实的一帧间隔内电机绝不可能转过半圈**（1ms 控制周期下差几个刻度而已）。所以 |delta| 超过 4096（半圈）必然是"跨圈假象"而非真实运动：
  - delta 为很大的正数 → 实际是反转跨过 0 点（如 3 → 8190 假象为 +8187，实际为 3 − 8190 + 8192 = **+5**……方向反过来同理）→ 减 8192 修正；
  - delta 为很大的负数 → 正转跨过 0 点 → 加 8192 修正。
- 修正后的 `delta` 就是真实的增量刻度，乘 360/8192 换算成度，累加进 `total_angle_deg`。多圈连续角度就此形成。
- `s_last_raw` 更新为本帧，为下一帧做准备。

```c
    g_motor.last_update_ms = HAL_GetTick();
    g_motor.online = 1u;
}
```

**逻辑：** 记录"活着的证据"：当前系统毫秒时间戳 + 在线标志。任务循环会用时间戳做超时判断。

## 4. CAN 接收中断回调（第 90~112 行）

```c
void HAL_CAN_RxFifo0MsgPendingCallback(CAN_HandleTypeDef *hcan)
{
    CAN_RxHeaderTypeDef header;
    uint8_t data[8];

    if (hcan->Instance != CAN1)
    {
        return;
    }
    if (HAL_CAN_GetRxMessage(hcan, CAN_RX_FIFO0,
                             &header, data) != HAL_OK)
    {
        return;
    }

    g_can_rx_count++;

    if ((header.IDE == CAN_ID_STD) && (header.StdId == GM6020_RX_ID))
    {
        g_can_rx_motor_count++;
        FeedbackDecode(data);
    }
}
```

**逐句逻辑：**
- 函数名是 HAL 规定的**弱回调**：CubeMX 生成的 HAL 中断处理函数内部会调用这个固定名字的函数，用户重写它来接管"收到帧"事件。
- `hcan->Instance != CAN1`：STM32 有多路 CAN，只处理 CAN1 的（本项目只用 CAN1）。
- `HAL_CAN_GetRxMessage(...)`：**必须调用**：把帧从 FIFO 硬件邮箱读出（同时释放邮箱，否则 FIFO 满了就再也收不到）。不读 = 丢帧 + 死锁。失败直接返回。
- `g_can_rx_count++`：先无条件计总帧数——排障第一问永远是"线上有数据吗"。
- 然后过滤：标准帧（IDE == CAN_ID_STD）且 ID 是本电机反馈 ID 才计数并解码。扩展帧、别的电机帧直接忽略。

**中断里做的事越少越好**，这里只做"取数 + 解码 + 更新状态"，控制计算全在任务里，是典型的"中断产数据、任务做决策"分工。

## 5. GM6020_SendCurrent 电流发送（第 116~143 行）

```c
void GM6020_SendCurrent(int16_t current)
{
    CAN_TxHeaderTypeDef tx_header;
    uint8_t tx_data[8] = {0};
    uint32_t mailbox;

    if (current > GM6020_CURRENT_MAX)
    {
        current = GM6020_CURRENT_MAX;
    }
    if (current < -GM6020_CURRENT_MAX)
    {
        current = -GM6020_CURRENT_MAX;
    }
```

**逻辑：** 入口处先双向钳位到 ±10000——双保险（PID 输出限幅是第一道，这里第二道），即使上层 bug 传进来野值也不会伤到电机。

```c
    tx_header.StdId = GM6020_TX_ID;    /* 0x1FF（ID1~4） */
    tx_header.ExtId = 0u;              /* 用标准帧，扩展 ID 无意义 */
    tx_header.IDE = CAN_ID_STD;        /* 声明：这是标准帧 */
    tx_header.RTR = CAN_RTR_DATA;      /* 数据帧（非远程请求帧） */
    tx_header.DLC = 8u;                /* 数据长度 8 字节 */
    tx_header.TransmitGlobalTime = DISABLE;  /* 不附加时间戳 */
```

**逐句逻辑：** 协议五要素：给谁（StdId）、哪种帧（IDE/RTR）、带多少数据（DLC）。`tx_data` 初始化 `{0}`：8 字节里本电机只用 Byte0/1，其余字节必须置 0 而不是留随机值——这条报文是按字节分给 4 个电机的，垃圾数据会变成发给别的电机的电流指令。

```c
    tx_data[0] = (uint8_t)((uint16_t)current >> 8);
    tx_data[1] = (uint8_t)((uint16_t)current & 0xFF);

    (void)HAL_CAN_AddTxMessage(&hcan1, &tx_header, tx_data, &mailbox);
}
```

**逐句逻辑：**
- 发送是接收的逆过程：16 位电流值拆成高字节（右移 8 位）、低字节（与 0xFF 取低 8 位）。先转 `uint16_t` 再移位，保证是按无符号位操作；接收端按 `int16_t` 重组回有符号值，约定闭环。
- `(void)` 显式忽略返回值：发送队列满时 HAL 返回忙，这里选择静默丢弃本帧——1ms 周期下丢一帧无感；如果将来要严谨，应在这里加错误计数。

# 五、control_task.h —— 控制任务的"说明书"

```c
/*
 * 串级 PID 控制任务（FreeRTOS 任务，周期 1 ms）：
 *   外环：角度环  -> 输出目标速度 (rpm)
 *   内环：速度环  -> 输出电流值
 */
void MotorControlTask(void const *argument);
```

**逻辑：** 只暴露一个入口函数，名字必须与 CubeMX 里给任务填的入口名**完全一致**（CubeMX 按名字生成 `osThreadDef`/`osThreadCreate`）。`void const *argument` 是 FreeRTOS 任务入口的固定签名（参数从任务创建时传入，本项目不用）。

**串级（Cascade）PID 的核心思想也在这里一句话点透：** 不让一个 PID 直接从角度跳到电流，而是分两层——外环"角度差多少"算出"该以多快的速度追"，内环"速度差多少"算出"该给多大电流"。分层后每层都简单、好调，且内环速度环天然抑制外环的激进输出。

**逐句逻辑：**
- 两个条件的"或"：从没收到过帧（`online==0`），或最近一帧距今超过 100ms（`HAL_GetTick()` 是 HAL 的 1ms 系统节拍，减法是免费的超时判断，无溢出之忧——两个无符号 32 位时间相减在回绕时依然正确，这是嵌入式时间比较的经典技巧）。
- 掉线处理三连：**清标志、Reset 两个 PID（防重新上线瞬间旧积分爆炸）、continue 不发一帧**。关键在 continue——掉线还发指令毫无意义，而且清零状态保证重新上线是"干净开局"。
- 在线则置 `g_motor_online=1` 供 Ozone 观察。

#### 第 3 步：目标初始化（第 100~107 行）

```c
        if (s_target_initialized == 0u)
        {
            g_target_angle_deg = g_motor.total_angle_deg;
            s_target_initialized = 1u;
            PID_Reset(&s_angle_pid);
            PID_Reset(&s_speed_pid);
        }
```

**逻辑：** 第一次确认电机在线后，**把"当前所在位置"设为目标位置**。为什么：如果上电目标默认是 0° 而电机实际在 123°，一上电就会以最大速度狂转到 0°，危险。设成当前位置 → 初始误差为 0 → 电机原地不动，等人（在 Ozone 里）下指令。再 Reset 一次双保险清状态。

#### 第 4 步：更新观察变量（第 109~112 行）

```c
        g_motor_angle_deg  = g_motor.total_angle_deg;
        g_motor_speed_rpm  = (float)g_motor.speed_rpm;
        g_angle_error_deg  = g_target_angle_deg - g_motor_angle_deg;
```

**逻辑：** 把内部状态"镜像"到观察变量，供波形显示。误差在这里顺手算一份给 Ozone 看（PID_Calc 内部还会自己再算一次，两边独立，观察变量纯粹为了显示）。

#### 第 5 步：外环——角度 → 目标速度（第 114~118 行）

```c
        target_speed = PID_Calc(&s_angle_pid,
                                g_target_angle_deg,
                                g_motor_angle_deg);
        g_target_speed_rpm = target_speed;
```

**逻辑：** 外环输入"目标角度 vs 实际角度"，输出"应该以多少 rpm 旋转"。角度差得远 → 目标速度大；逼近目标 → 目标速度自动缩小。**这就是串级控制的精髓：外环不直接管电流，只给内环下达"速度意图"，把电流怎么给的难题交给内环。**

#### 第 6 步：内环——速度 → 电流（第 120~124 行）

```c
        current = PID_Calc(&s_speed_pid,
                           target_speed,
                           g_motor_speed_rpm);
        g_target_current = current;
```

**逻辑：** 内环输入"目标速度（来自外环）vs 实际转速（来自电机反馈）"，输出电流。速度跟不上 → 大电流加速；超速 → 负电流刹车。由于速度环周期也是 1ms 且电机机械响应比电流环慢得多，这个内环足够"硬"。

#### 第 7 步：下发 + 节拍（第 126~129 行）

```c
        GM6020_SendCurrent((int16_t)current);
        osDelay(1);
```

**逻辑：** 电流 float → `int16_t` 强转（协议要求整数，舍入误差远小于电机非线性，可忽略），发送。`osDelay(1)` 挂起任务 1ms——既是与电机反馈节奏匹配的**控制周期**，又让出 CPU 给其它任务（FreeRTOS 协作的体现）。整个循环周而复始，构成 1kHz 的双环伺服。
